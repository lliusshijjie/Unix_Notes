# 定时器调度器：第三阶段实现框架

## 阶段目标

将“定时任务调度”和“任务实际执行”解耦：

> **调度线程只负责发现到期任务，回调统一投递到之前实现的线程池执行。**

---

## 一、接入线程池

定时器调度器持有或引用一个线程池：

```cpp
class MyTimerScheduler {
public:
    explicit MyTimerScheduler(ThreadPool& executor);

private:
    ThreadPool& executor_;
};
```

调度线程不再直接调用：

```cpp
callback();
```

而是：

```cpp
executor_.submit(std::move(callback));
```

---

## 二、批量取出到期任务

每次调度线程被唤醒后，不只处理一个任务，而是一次取出所有已经到期的任务：

```text
获取当前时间
    ↓
循环检查堆顶
    ↓
堆顶已到期：取出
    ↓
继续检查下一个
    ↓
批量投递线程池
```

避免大量任务同时到期时，调度线程频繁等待和唤醒。

---

## 三、重新设计周期任务状态

接入线程池后，回调不是立即执行，而是异步执行，因此周期任务需要区分：

```cpp
enum class TimerState {
    Pending,     // 等待到期
    Submitted,   // 已投递线程池
    Executing,   // 正在执行，可选
    Cancelled
};
```

需要保证：

* 周期任务本次执行完成后再重新调度；
* 执行期间取消后不再重新入堆；
* 同一个周期任务不会并发执行多次；
* 投递线程池失败时正确处理状态。

---

## 四、封装任务执行包装器

向线程池提交的不是原始回调，而是包装后的任务：

```cpp
executor_.submit([
    this,
    id,
    interval,
    callback = std::move(callback)
]() mutable {
    // 执行回调
    // 捕获异常
    // 更新任务状态
    // 周期任务重新入队
});
```

包装器负责：

* 执行用户回调；
* 捕获回调异常；
* 检查任务是否被取消；
* 重新调度周期任务；
* 清理一次性任务状态。

---

## 五、处理线程池拒绝任务

线程池可能因为以下原因拒绝提交：

* 已经停止；
* 任务队列已满；
* 正在关闭。

定时器需要明确处理策略：

```text
一次性任务提交失败
    → 删除状态或记录失败

周期任务提交失败
    → 停止该任务，或者重新调度
```

第三阶段先选择简单策略：

> 提交失败则取消该定时任务，不阻塞调度线程。

---

## 六、完善停止流程

明确 `stop()` 时的行为：

```text
停止接受新定时任务
    ↓
唤醒调度线程
    ↓
调度线程退出
    ↓
未到期任务全部取消
    ↓
已经投递线程池的任务由线程池决定是否完成
```

建议接口：

```cpp
void stop();
```

第一版停止语义可以定义为：

* 不再接受新任务；
* 未到期任务不执行；
* 已经提交到线程池的任务继续执行；
* 周期任务执行结束后不再重新调度。

---

## 七、线程池所有权

需要明确两种关系中的一种。

### 推荐：外部线程池

```cpp
MyTimerScheduler scheduler(thread_pool);
```

定时器不负责关闭线程池，生命周期要求：

```text
线程池先启动
    ↓
定时器启动
    ↓
定时器停止
    ↓
线程池停止
```

这样线程池可以被 RPC、网络事件和定时器共同使用。

---

## 八、第三阶段暂不实现

本阶段暂时不加入：

* 时间轮；
* Cron 表达式；
* 固定频率追赶；
* 定时任务持久化；
* 多调度线程；
* 调度精度统计；
* 动态扩缩容；
* 无锁数据结构。

---

## 九、完成标准

第三阶段完成后，应验证：

1. 调度线程不再执行耗时回调。
2. 多个同时到期任务可以并发执行。
3. 一个慢任务不会阻塞其他定时任务的调度。
4. 周期任务不会出现重叠执行。
5. 周期任务执行过程中可以取消。
6. 停止调度器后，周期任务不会重新入队。
7. 线程池拒绝任务时不会导致状态泄漏。
8. 批量到期任务能够一次性取出并提交。

第三阶段的核心是：

> **调度器负责时间管理，线程池负责并发执行，并正确处理两者之间的任务状态与生命周期。**
